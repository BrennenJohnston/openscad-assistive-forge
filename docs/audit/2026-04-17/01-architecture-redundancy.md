- **OBSERVED** — produced directly by a tool / verified read.

- **UNVERIFIED** — flagged for follow-up; not used as the basis for any recommendation.

`src/js/color-utils.js` (83 lines) implements `normalizeHexColor`, `hexToRgb`, `isValidHexColor`. `colorjs.io` is the obvious candidate to compare against, but:

- `colorjs.io` is a `devDependency` (test-only); not in the runtime bundle.
- The runtime functions cover only `#RRGGBB` / `#RGB` parsing — a tiny subset of what `colorjs.io` does.
- Pulling `colorjs.io` into the runtime to replace 80 lines of trivial hex-parsing would add a multi-KB dependency for no functional gain.

**Verdict:** keep `color-utils.js` as-is; do **not** treat as shadowing. **OBSERVED + INFERRED (bundle-size assumption).**

### 2.4 In-house code that **may** be solvable by a library we already ship

- `path-bool` and `clipper2-js` are both in `dependencies` and both currently used (`path-bool` for boolean ops in `svg-preparer.js`, `clipper2-js` for offset in `svg-offset.js`). Clipper2 (the upstream C++ library that `clipper2-js` wraps) supports boolean operations natively; whether the JS port exposes the boolean API at full fidelity is **UNVERIFIED**. Phase 6 should investigate the API surface and bundle-size delta of dropping `path-bool` in favour of clipper2's `BooleanOp`. **Do not act in this audit.**
- `escapeHtml` lives in `html-utils.js` (one place — good). Audit notes that the codebase has **186 occurrences of `innerHTML =` across 21 files** (`Grep -count`). Phase 4 will check which of those are static strings vs user content; this is not a Phase 1 finding.

### 2.5 In-house code that does **not** shadow but is currently duplicated *inside* the project

- `cli/commands/extract.js#toJsonSchema()` (lines 18-220) and `src/js/schema-generator.js#toJsonSchema()` (lines 156-289) both convert `extractParameters()` output to JSON Schema. The two functions are *not* drop-in interchangeable today:
  - CLI emits `$schema: 'http://json-schema.org/draft-07/schema#'`; web emits `JSON_SCHEMA_DRAFT` (different constant).
  - CLI emits group as `{ name, label, collapsed, order }` for back-compat with older consumers (per the in-source comment); web emits `{ id, label, order }`.
  - CLI handles legacy `param.min` / `param.max`; web requires `param.minimum` / `param.maximum`.
  - CLI emits `'x-step'`; web's encoding is **UNVERIFIED**.
  - **Verdict:** This is an **intentional fork**, documented in source comments. Recommendation belongs in **Phase 6 / Decompose-First** — not a Quick Win. The right shape is one schema-generator with a `format: 'cli-legacy' | 'web'` knob, but designing that contract requires a deliberate API decision.

### 3.3 `src/js/schema-generator.js` — orphaned from runtime

- **OBSERVED:** No `src/` file imports it; the only consumer is `tests/unit/schema-generator.test.js`.
- **OBSERVED:** `cli/commands/extract.js` re-implements an equivalent function instead of importing this one (see §2.5).
- **INFERRED intent:** The module was probably meant as the canonical schema generator for both web and CLI surfaces, but the wiring was never completed.
- **Recommendation tier:** **Decompose-First / Defer-Design** — pick a single schema-generator owner and either (a) wire `extract.js` through it, or (b) move `schema-generator.js` under `cli/` and treat the web copy as future work. Either choice removes ~150 lines of duplication; both require an API decision first (see §2.5).

### 3.4 `src/js/animation-controller.js` — orphaned, but has a pinned reason

- **OBSERVED:** No `src/` file imports it. The file is 481 LOC.
- **INFERRED intent (verify in Phase 5):** prior CODE_AUDIT_FINDINGS notes refer to it as "intentional placeholder" / forward-looking. The file references `localStorage` 4 times, suggesting it was meant to manage scene-level animation presets.
- **Recommendation tier:** **Defer-Design** — either delete (with explicit ADR / changelog entry) or wire into `preview.js`. Recommendation is **not** to silently delete: file size (481 LOC) and presence of localStorage state interact with the storage-key reservation list.
